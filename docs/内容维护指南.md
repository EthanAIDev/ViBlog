# ViBlog 内容维护指南（Agent 工作流）

本项目已**纯静态化**：没有管理后台、没有写接口。所有内容的增删改都直接操作文件，
由 AI Agent（ZCode）代劳即可 —— 你只需要说"帮我加一篇文章/一个项目"。

## 一、站点架构速览

```
ViBlog/
├── src/pages/            # Astro 页面：首页、文章、项目与关于
├── src/components/       # 交互装置、文章筛选与公共组件
├── src/styles/global.css # AI 实验室设计令牌、布局与响应式规则
├── src/lib/              # 内容处理、3D 场景与阅读交互
├── scripts/sync-public.mjs # 素材同步与旧链接兼容
├── build-manifest.cjs    # 内容索引构建器
├── articles/             # 文章内容
│   ├── manifest.json     # 自动生成的文章索引（勿手改）
│   └── [文章ID]/
│       ├── index.md      # 正文（Markdown）
│       ├── meta.json     # 元数据
│       └── *.png/jpg     # 文章图片
└── projects/
    ├── manifest.json     # 自动生成的项目索引（勿手改）
    └── [项目ID]/
        ├── detail.json   # 项目详情
        └── images/       # 项目图片
```

## 二、新增一篇文章（对 Agent 说即可）

直接说：*"帮我写一篇关于 XXX 的文章，要点是……"*
Agent 会执行以下步骤：

1. 新建 `articles/<新ID>/`（ID 用 8 位数字，如 `10000004`）；
2. 写 `index.md`（正文）和 `meta.json`（元数据）；
3. 正文里的图片放进同目录，引用写相对文件名：`![说明](xxx.png)`；
4. 运行 `npm run build-manifest` 重建索引；
5. 重新启动开发服务，打开 `http://localhost:3000/articles/<新ID>/` 验证。生产发布运行 `npm run build`。

**meta.json 格式：**

```json
{
  "id": "10000004",
  "title": "文章标题",
  "type": "教程",              // 类型：教程 / 实地笔记 / 构建日志 / 随笔（会自动生成分类过滤器）
  "date": "2026-09-12",
  "displayDate": "2026.09.12",
  "tags": ["RAG", "Agent"],    // 会自动生成标签过滤器
  "summary": "列表页显示的摘要，一两句话。",
  "status": "published"        // published 才会出现在列表；draft 可存草稿
}
```

**正文支持的能力（构建期渲染，交互按需加载）：**

- 标准 Markdown + GFM 表格
- 代码高亮 + 一键复制（rehype-highlight）
- 数学公式：行内 `$E=mc^2$`，块级 `$$...$$`（KaTeX）
- 流程图：` ```mermaid ` 代码块
- 提示块：引用首行写 `[!NOTE]` / `[!TIP]` / `[!WARNING]` / `[!IMPORTANT]`
- 图片点击放大（Lightbox）
- Obsidian 风格图片语法 `![[xxx.png]]` 也兼容

## 三、新增一个项目（对 Agent 说即可）

直接说：*"帮我加一个项目，叫 XXX，用了什么技术……"*
Agent 会执行：

1. 新建 `projects/<项目ID>/images/`（ID 如 `p004`）；
2. 写 `detail.json`：

```json
{
  "id": "p004",
  "title": "项目名称",
  "displayName": "英文或简短展示名（可选，不填则使用 title）",
  "focus": "项目方向（可选）",
  "cardSummary": "首页与列表的精简摘要（可选，不填则使用 summary）",
  "technologies": ["技术 A", "技术 B"],
  "summary": "一句话摘要（列表页卡片显示）",
  "overviewMd": "## 项目概述\n支持 Markdown",
  "techStackMd": "| 类别 | 技术 | 作用 |\n|---|---|---|\n| ... | ... | ... |",
  "implementationMd": "### 1. 架构\n...",
  "links": { "github": "https://github.com/...", "docs": "" },
  "gallery": [
    { "src": "images/01-xxx.png", "alt": "截图说明", "caption": "截图说明" }
  ]
}
```

3. 项目截图放进 `images/`（建议 16:9，首张是封面可另配 `cover.svg`）；
4. 运行 `npm run build-manifest`；
5. 重新启动开发服务，打开 `http://localhost:3000/projects/p004/` 验证。

## 四、其他修改

| 想改什么 | 改哪里 |
|---|---|
| 首页介绍与装置演示文案 | `src/components/Lab.tsx` |
| 首页内容布局 | `src/pages/index.astro`（文章和项目自动读取） |
| 关于页自我介绍 / 经历 / 技术背景 | `src/pages/about/index.astro` |
| 社交链接 / 邮箱 | 公共页眉页脚在 `src/layouts/Layout.astro`，个人联系在关于页 |
| 站点标题 / favicon | `src/layouts/Layout.astro` 与 `public/favicon.svg` |
| 主题色 / 字体 / 圆角 / 响应式 | `src/styles/global.css` 与 `DESIGN.md` |

关于页直接修改 `src/pages/about/index.astro`。公共样式与令牌位于 `src/styles/global.css`，交互位于 `src/components/` 与 `src/lib/`。Astro 自动为构建资源生成哈希，无需手工升级样式或脚本版本号。

## 五、本地运行

```bash
npm start        # http://localhost:3000
npm run build-manifest   # 新增/修改文章或项目后重建索引
npm run build            # 生成可发布的 dist/（自动重建索引和同步素材）
```

部署到 Cloudflare Pages 等静态托管时，配置构建命令 `npm run build`、输出目录 `dist`。托管运行时无需 Node 进程。原 `.html` 入口会自动跳转到新路径。
