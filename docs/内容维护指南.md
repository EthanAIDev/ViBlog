# ViBlog 内容维护指南（Agent 工作流）

本项目已**纯静态化**：没有管理后台、没有写接口。所有内容的增删改都直接操作文件，
由 AI Agent（ZCode）代劳即可 —— 你只需要说"帮我加一篇文章/一个项目"。

## 一、站点架构速览

```
ViBlog/
├── index.html            # 首页（Hero / 数据条 / 最新文章 / 精选项目）
├── posts.html            # 文章列表（搜索 + 分类 + 标签过滤 + 分页）
├── article.html          # 文章详情（Markdown 渲染 / 目录 / 代码高亮 / 公式 / 图表）
├── projects.html         # 项目列表（分页）
├── project.html          # 项目详情（概述 / 技术栈 / 实现方案 / 图片画廊）
├── about.html            # 关于我（纯静态内容，直接改这个文件）
├── styles.css            # Dark AI Lab 设计系统（方案 A）
├── script.js             # 前端逻辑 + 动效引擎（无任何后台代码）
├── server.js             # 纯静态文件服务器（只读，无 API）
├── build-manifest.js     # 内容索引构建器
├── articles/             # 文章内容
│   ├── manifest.json     # 自动生成的文章索引（勿手改）
│   └── [文章ID]/
│       ├── index.md      # 正文（Markdown）
│       ├── meta.json     # 元数据
│       └── *.png/jpg     # 文章图片
└── projects/
    ├── manifest.json     # 自动生成的项目索引（勿手改）
    └── [项目ID]/
        ├── detail.json   # 项目详情
        └── images/       # 项目图片
```

## 二、新增一篇文章（对 Agent 说即可）

直接说：*"帮我写一篇关于 XXX 的文章，要点是……"*
Agent 会执行以下步骤：

1. 新建 `articles/<新ID>/`（ID 用 8 位数字，如 `10000004`）；
2. 写 `index.md`（正文）和 `meta.json`（元数据）；
3. 正文里的图片放进同目录，引用写相对文件名：`![说明](xxx.png)`；
4. 运行 `npm run build-manifest` 重建索引；
5. 打开 `http://localhost:3000/article.html?id=<新ID>` 验证。

**meta.json 格式：**

```json
{
  "id": "10000004",
  "title": "文章标题",
  "type": "教程",              // 类型：教程 / 实地笔记 / 构建日志 / 随笔（会自动生成分类过滤器）
  "date": "2026-09-12",
  "displayDate": "2026.09.12",
  "tags": ["RAG", "Agent"],    // 会自动生成标签过滤器
  "summary": "列表页显示的摘要，一两句话。",
  "status": "published"        // published 才会出现在列表；draft 可存草稿
}
```

**正文支持的能力（article.html 自动处理）：**

- 标准 Markdown + GFM 表格
- 代码高亮 + 行号 + 一键复制（highlight.js）
- 数学公式：行内 `$E=mc^2$`，块级 `$$...$$`（KaTeX）
- 流程图：` ```mermaid ` 代码块
- 提示块：引用首行写 `[!NOTE]` / `[!TIP]` / `[!WARNING]` / `[!IMPORTANT]`
- 图片点击放大（Lightbox）
- Obsidian 风格图片语法 `![[xxx.png]]` 也兼容

## 三、新增一个项目（对 Agent 说即可）

直接说：*"帮我加一个项目，叫 XXX，用了什么技术……"*
Agent 会执行：

1. 新建 `projects/<项目ID>/images/`（ID 如 `p004`）；
2. 写 `detail.json`：

```json
{
  "id": "p004",
  "title": "项目名称",
  "summary": "一句话摘要（列表页卡片显示）",
  "overviewMd": "## 项目概述\n支持 Markdown",
  "techStackMd": "| 类别 | 技术 | 作用 |\n|---|---|---|\n| ... | ... | ... |",
  "implementationMd": "### 1. 架构\n...",
  "links": { "github": "https://github.com/...", "docs": "" },
  "gallery": [
    { "src": "images/01-xxx.png", "alt": "截图说明", "caption": "截图说明" }
  ]
}
```

3. 项目截图放进 `images/`（建议 16:9，首张是封面可另配 `cover.svg`）；
4. 运行 `npm run build-manifest`；
5. 打开 `http://localhost:3000/project.html?id=p004` 验证。

## 四、其他修改

| 想改什么 | 改哪里 |
|---|---|
| 首页 Hero 文案 / 状态徽章 | `index.html` 直接改 |
| 首页统计条文案 | `index.html`（文章数、项目数自动统计，不用改） |
| 关于页自我介绍 / 时间轴 | `about.html` 直接改 |
| 社交链接 / 邮箱 | 各页面 header/footer + `about.html`（多处，让 Agent 全局替换） |
| 站点标题 / favicon | 各 HTML `<head>` |
| 主题色 / 字体 / 圆角 / 浅色主题 | `styles.css` 顶部 `:root` 与 `[data-theme="light"]` 设计变量 |

**改 `styles.css` 或 `script.js` 后必须升级版本号**：全站引用形如
`styles.css?v=20260918`、`script.js?v=20260918`，两个文件要**一起**升（日期式即可），
否则访客浏览器会继续使用旧缓存，看不到改动。

## 五、本地运行

```bash
npm start        # http://localhost:3000
npm run build-manifest   # 新增/修改文章或项目后重建索引
```

部署到 Cloudflare Pages 等静态托管时，直接推仓库即可（`_headers` 已配置缓存策略）；
托管平台只需静态文件能力，不需要 Node 进程。
